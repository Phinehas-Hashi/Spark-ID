Current availability: not yet public

No third-party app registration, OAuth endpoints, SDK, client IDs, tokens, or developer API keys are currently issued. Do not use the first-party Appwrite project ID or Android session cookie as an external integration.

Planned developer journey

  1. Create a developer organization and verify contact details.
  2. Register a web, mobile or server application; obtain a public client identifier.
  3. Configure exact HTTPS redirect URIs (native apps use an approved secure redirect pattern).
  4. Choose minimum scopes and submit branding/privacy details for review.
  5. Integrate authorization-code flow with PKCE (S256), state and nonce as applicable.
  6. Validate issuer, audience, signature, expiry and nonce of ID tokens using published keys; enforce access-token audience and scopes on APIs.
  7. Offer users a clear consent and connected-app revocation experience.

Proposed protocol contract

Target: OAuth 2.1-aligned authorization code + PKCE and OpenID Connect. Final endpoints, supported scopes, discovery document, signing algorithms, token lifetimes and policies will be published after the authorization server exists and has been tested.

Client → Spark ID authorization endpoint
       → User authenticates + grants consent
       → Registered redirect URI receives short-lived code
       → Client exchanges code with PKCE verifier
       → Client validates issued tokens
       → User may revoke connected-app access

Security requirements

  • Never ask users to type their Spark ID password inside a third-party app.
  • Never embed privileged server secrets in mobile apps, browser JavaScript or public repositories.
  • Require strict redirect URI matching, PKCE S256, state protection, short-lived codes and replay prevention.
  • Apply least-privilege scopes, rate limits, auditable consent and credential rotation.
  • Separate account email verification from legal identity checks, KYC, and financial authorization.
  • Do not use GitHub Pages as a token-issuing server. A secured backend is required.

Implementation milestones

01 · Design: developer guide and first-party Developer Hub (current).

02 · Infrastructure: secured authorization backend, key management, discovery and token verification.

03 · Console: authenticated developer onboarding, app registration, redirect URI review and credential management.

04 · Pilot: test integration with one Spark Stack app, independent security review, then public SDKs and documentation.
